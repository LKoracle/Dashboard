## 通过的验证

1. 零值可写入并按定点数读取，不被当成缺失。
2. 同一数据项同一日期重复写入被唯一约束拦截。
3. 指标数据项不能改到其他项目。
4. 漏斗步骤不能引用其他项目的数据项。
5. 指标值不能引用其他指标的口径版本。
6. 指标值不能关联其他项目的写入批次。
7. VALID 状态不能写入 NULL 数值。
8. PENDING 状态不能带数值。
9. 数据项 subject_key 必须与功能 ID 对应。
10. 同一漏斗的步骤顺序不能重复。
11. 当前口径指针不能指向其他指标的版本。
12. 布尔开关不能写入 0/1 以外的数值。

测试使用事务回滚；负向测试的连接在错误后关闭，未提交的数据由 InnoDB 回滚。自增 ID 可能出现空档，这是回滚测试的正常结果。

## 物理存储约定

- 主键使用有符号 BIGINT AUTO_INCREMENT；三张多对多关系表采用联合主键。
- 通用逻辑类型 TIMESTAMP 落为 DATETIME(6)，应用连接须显式设置 UTC 会话时区；统计日使用 DATE，业务时区默认 Asia/Shanghai。
- UTF-8 使用 utf8mb4，排序规则为 utf8mb4_0900_as_cs，名称及标识比较区分大小写；应用对 name_key 的标准化要保持一致。
- 比例保存 0～100，数值使用 DECIMAL(24,6)。字段约束不能代替指标口径版本驱动的服务端验证。
- 外键使用默认 RESTRICT 行为；不级联清除历史事实、版本或日志。
- row_version 默认 1，应用须在 UPDATE 条件中校验旧值并递增，不依赖默认值实现并发控制。
- 预留 data_source、data_source_mapping、auth_session 三张表；建表不代表已接通云文档或认证。
